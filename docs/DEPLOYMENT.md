# Deployment

## Option A – Docker Compose (full stack, local or any VM)

```bash
cp .env.example .env              # set JWT_SECRET; optionally GEMINI_API_KEY
docker compose up --build
```

| Service | URL | Role |
|---|---|---|
| postgres | localhost:5432 | PostgreSQL 16 with the SAP-style schema |
| mlflow | http://localhost:5000 | Experiment tracking and model registry UI |
| trainer | – | One-shot: `make all` (data → train → drift report → evaluation), then exits |
| api | http://localhost:8000/docs | FastAPI (starts after the trainer succeeds) |
| dashboard | http://localhost:8501 | Streamlit, calling the API (`SUPPLYSIGHT_API_URL=http://api:8000`) |

Model artifacts are shared through the `artifacts` volume. To re-run training: `docker compose run --rm trainer`.

## Option B – Render free tier (API + dashboard)

1. Push the repository to GitHub.
2. In Render: **New → Blueprint**, select the repo. `render.yaml` defines two free web services. Each build
   installs `.[serve]`, generates the synthetic data and trains the models (≈ 2–3 min), so no database service is
   needed (SQLite on the instance disk).
3. Set `JWT_SECRET` (auto-generated by the blueprint) and optionally `GEMINI_API_KEY`.
4. Put the URLs in the README. Free instances sleep after inactivity; the first request takes ~1 minute.

## Option C – Azure App Service / AWS EC2 free tier

```bash
# on an Ubuntu VM (EC2 t2.micro / t3.micro, Azure B1s)
sudo apt-get update && sudo apt-get install -y docker.io docker-compose-plugin
git clone https://github.com/<you>/supplysight && cd supplysight
cp .env.example .env && sudo docker compose up -d --build
```

Open ports 8000 and 8501 in the security group / NSG, or put Nginx/Caddy in front with TLS. On a 1 GB instance,
skip the `mlflow` service (`docker compose up -d postgres trainer api dashboard`).

## Production checklist

- Change `JWT_SECRET`; replace demo users with SSO (Azure AD / SAP IAS) mapped to the four roles.
- Use managed PostgreSQL; schedule `scripts/retrain.py` weekly (cron / GitHub Actions / Airflow).
- Keep `GEMINI_API_KEY` in a secret store; review what data may leave the network (see DATA_PRIVACY.md).
- Replace the generator with SAP extracts (OData / BAPI / SLT) into the same schema.
